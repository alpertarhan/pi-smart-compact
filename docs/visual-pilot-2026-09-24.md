# Visual evidence pilot — 2026-09-24

> **Scope:** Historical pilot report, dated 2026-09-24. One model, synthetic scenarios, one sample each; not production or cross-model evidence. Results are kept as recorded.
> Current documentation for Pi Continuity (the `pi-smart-compact` package):
> [guide](./guide.md) · [configuration](./configuration.md) ·
> [evaluation](./evaluation.md) · [documentation index](./README.md).

## Decision

Keep `visualArchiveEnabled` **off by default**. The bitmap path preserved every
queried detail in these three synthetic scenarios, but used **65.7% more input
tokens** than carrying the same excerpts as text (6,021 vs 3,634). This pilot does
not support a token-saving claim or automatic promotion of visual mode.

Machine-readable observations, including original answers and provider usage:
[`visual-pilot-2026-09-24.json`](./visual-pilot-2026-09-24.json).

## Method and authorization

- User approved exactly one Sonnet 5 pilot, up to **9 requests**. All nine ran once;
  no retries or additional model requests were used for analysis.
- Model: `anthropic/claude-sonnet-5`, `anthropic-messages`, configured OAuth access.
- Three entirely synthetic scenarios: Turkish/code identifiers, diagnostic logs
  with a malicious quoted instruction, and evidence spanning two PNG pages.
- Three representations per scenario: fixed short summary; that summary plus text
  excerpts; that summary plus the same excerpts rendered as PNGs.
- The summaries were **hand-authored controls**, deliberately omitting six queried
  details. They were not generated by EESV. Summary-only results cannot be read as
  EESV quality scores or evidence that EESV necessarily drops those details.
- Production source selection, scrubbing, renderer, native session reconstruction,
  and image injection were used. No project files, real conversation, credentials,
  or private logs were sent. No tools were exposed to the model.
- Each request asked for nine exact string fields: two summary constraints, six
  evidence details, and one genuinely absent fact. The instruction for unavailable
  information was `UNKNOWN`. Answer keys were not included in requests.
- Variant order rotated across scenarios. Cache retention was `none`; every
  response reported zero cache-read/write tokens. Requests were sequential, capped
  at 1,024 output tokens and 60 seconds, with SDK retries disabled. One observation
  per cell is not a latency or accuracy distribution.
- Bitmap requests used their production reading guide. The text control used a
  shorter equivalent textual guide and the same wrapped source pages. Input counts
  therefore include representation-specific framing as well as the evidence.

Summary-only correctly answered `UNKNOWN` for unavailable details, giving **27/27
grounded responses**, not hallucinations. The six omitted evidence fields per
scenario account for its lower full-evidence score. Both enriched representations
recovered all 18 evidence-only values, including `Çağrı Işık`, `iş-kuyruğu-özel`,
`now >= expiresAt`, and identifiers spanning the two-page archive. All preserved
the no-publish constraint; the malicious quoted log instruction was not followed
in this small sample. This is not a general prompt-injection safety proof.

Total catalog estimate for all nine requests: **USD 0.031780**. Actual reported
input+output usage was 1,445 tokens for summary, 3,977 for text evidence, and 6,332
for bitmap evidence. Image-token counts were not separately exposed; the input
differences include the reading guides and provider message framing.

## Rendering observations and fixed defect

| Scenario | Frames | PNG bytes | Render ms | Image planning allowance |
|---|---:|---:|---:|---:|
| Turkish/code | 1 | 104,652 | 49 | 2,296 |
| Logs/constraints | 1 | 124,417 | 59 | 2,656 |
| Two pages | 2 | 352,367 | 159 | 6,992 |

These are local one-shot measurements. Planning allowances remain conservative;
this single model sample is insufficient to replace them with a cheaper estimate.

Offline preparation exposed a real two-page bug: resvg's native AbortSignal
binding is single-use, so reusing one signal on the second render throws
`InvalidArg` on both Node and Bun. Each page now receives a fresh signal composed
from the same parent cancellation signal. A failing two-page regression test was
added before the one-line fix; it now passes. This fix preceded all live requests.

## Reproduce

From a development checkout with Pi credentials configured:

```bash
# Offline: build/validate synthetic pages and request plans, no model request.
bun run scripts/visual-pilot.ts --model=anthropic/claude-sonnet-5

# Explicitly authorized live execution: up to nine quota-consuming requests.
# Choose a NEW output path; existing reports are not overwritten.
bun run scripts/visual-pilot.ts --live --model=anthropic/claude-sonnet-5 \
  --output=/tmp/visual-pilot-new.json
```

The script stops on the first provider/transport failure and preserves available
observations. Invalid answer formatting is recorded as a score failure, not retried.
Reports contain synthetic answers and usage, never image base64 or auth material.

## What this does not establish

- EESV's real summary fidelity or total cost of generating that summary.
- Agent willingness to call checkpoint/rewind, production task completion, or
  correctness over repeated compactions.
- Dense, near-maximum archives, other languages, providers, models, cache warming,
  quotas under load, or outages.
- A bitmap token advantage. The examples have repetitive prose and moderate text
  density, which favors text tokenization. Different layouts/corpora require a new
  explicitly authorized comparison, not extrapolation from this result.

For the minimum-context goal, keep automatic local trimming, bounded textual
recall, and background EESV as the primary path. Retain bitmap mode as an opt-in
experiment until representative evidence justifies it; this pilot changes no
model route, default, global setting, or deployment.
